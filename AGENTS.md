# AGENTS.md — briefing for the next coding agent

This is a live webinar demo project: "Your First APEXlang App — From Nothing to Running in a Single Session." Everything the demo needs is in this folder. If you're a coding agent being handed this project, read the whole file before touching anything.

## What this project is

The demo proves you can go from an empty Mac to a live Oracle APEX 26.1 application running on OCI Always Free, in under an hour, without opening a browser except to see the finished app. The presentation is a self-contained HTML deck (with keyboard nav + optional "Run this in my terminal" buttons); the scripts are idempotent bash that install/provision/deploy each step.

## Non-obvious things you MUST know

### 1. Always Free ADBs only exist in the tenancy's HOME region

`oci session authenticate` happily creates a profile for any region you pick, and every call then fails with `TenantNotFound` / `NotAuthenticated` if it isn't the tenancy's home region. Find it with `oci iam region-subscription list` (the row with `is-home-region: true`), or decode the session token: the JWT has no region claim, so probe `oci iam tenancy get --region <r>` across candidates. The scripts read the region from the OCI profile that sign-in writes (`oci_region` in `_lib.sh`); `OCI_REGION=<region>` overrides.

### 2. `OCI_CLI_AUTH=security_token` is required for session-token profiles

`oci session authenticate` creates a profile with `security_token_file=...`, but the OCI CLI default is `--auth api_key`. You get 401 NotAuthenticated on every call until you set `OCI_CLI_AUTH=security_token` (or pass `--auth security_token` on every command). Every script that touches `oci` exports this at the top.

### 3. Always Free `adb-free-count` quota lags 30–60s after termination

After `oci db autonomous-database delete`, the "you have 2 Always Free ADBs" counter takes 30–60 seconds to release. `07-provision-adb.sh` has a 10× × 60s retry loop that catches `QuotaExceeded` and retries. Do not remove it.

### 4. SQLcl 26.1's bundled JRE is Java 16 — APEXlang needs Java 17+

Without Java 21, `apex generate` crashes with `UnsupportedClassVersionError: class file version 61.0`. `04-install-java21.sh` installs `openjdk@21` and appends `JAVA_HOME` + PATH exports to `~/.zshrc`. If you touch that script, keep the "idempotent grep before append" logic — running it twice must not duplicate the exports.

### 5. SQLcl mangles multi-line PL/SQL inside `sql <<EOF ... EOF`

SQLcl's parser splits BEGIN..END/ blocks on interior newlines when read from stdin heredoc, producing "Unknown Command" for every interior line. Two reliable patterns:
- Write SQL to a temp file with shell-substituted values, invoke as `sql @/tmp/file.sql` (this is what `08-setup-workspace.sh` does).
- Wrap the target call in `EXECUTE IMMEDIATE 'BEGIN …; END;' USING :var` — single string, no line-boundary issues.

Do NOT use SQLcl's `&` DEFINE substitution when values are shell-generated: `SET DEFINE OFF` breaks it, and `SET DEFINE ON` fights with any `&` characters in secrets.

### 6. `--wait-for-state` values differ by operation

- On operations that return a work-request (create/delete/update): valid values are `ACCEPTED | IN_PROGRESS | FAILED | SUCCEEDED`. Use `SUCCEEDED`.
- On `get` operations: `--wait-for-state` doesn't exist — poll manually.
- Some ADB operations that block on lifecycle: use resource lifecycle values (`AVAILABLE`, `TERMINATED`, `STOPPED`).

### 7. `oci db autonomous-database generate-wallet` has no `--force` flag

If `wallet.zip` already exists, generate-wallet errors. `07-provision-adb.sh` does `rm -f` on the target file before generating.

### 8. Antigravity.app 2.x no longer ships a CLI binary

On a Mac with Antigravity 2.x installed, `command -v antigravity` can still fail, because the per-user symlink at `~/.antigravity/antigravity/bin/antigravity` points to a path that no longer exists in the current `.app` bundle (the CLI shipped in early releases, was removed later). `01-check-agent.sh` detects the `.app` bundle directly rather than trusting `command -v`.

### 9. `have()` in `_lib.sh` verifies executability, not just PATH presence

Broken symlinks (like the dead antigravity one) show up in `command -v` but aren't runnable. `have()` follows the link and checks `[ -x ]`. If you add new commands to check, use `have` not raw `command -v`.

## APEXlang syntax discoveries

The `scriptFile` property is only valid inside the `deinstall { }` block. There is NO `install { scriptFile: X }` — install scripts are a full component (`installScript`) that lives inside `supportingObject`. Properties are grouped by their `groupName` from the metametadata and must be nested inside a block of that name:

```apx
supportingObject (
    deinstall { scriptFile: deinstall-script.sql }
    advanced  { includeInAppExport: true }

    installScript sales-schema (
        script    { content: @install-scripts/sales-schema.sql }
        execution { sequence: 10 }
    )
)
```

- The identifier (`sales-schema`) IS the `name` property — do NOT restate it as `identification { name: … }`.
- The `content` property references an external file via `@relative/path.sql`.
- The file lives at `supporting-objects/install-scripts/sales-schema.sql`.

### Region source syntax (this took an hour to figure out)

Regions with SQL sources need `location` + `type` + `sqlQuery` all inside the `source { }` block, and the values are **camelCase aliases** — not the enum names from the metametadata.

```apx
region my-report (
    name: Some Report
    type: interactiveReport
    layout {
        sequence: 20
        slot: body
    }
    source {
        location: localDatabase        # NOT 'LOCAL' — validator lists valid values on error
        type: sqlQuery                 # NOT 'SQL'
        sqlQuery: ```sql
            SELECT id, region, amount FROM sales ORDER BY sale_date DESC
        ```
    }
)
```

Valid `location` values: `localDatabase | restEnabledSql | restSource | jsonDualityView | jsonSource | sampleData`
Valid `type` values (for local location): `sqlQuery | tableView | functionBody | propertyGraph`

### THE rule that cost the most time: never author a singleton `attributes ( )`

Region plugins (interactiveReport, chart, …) each have a one-to-one `attributes` child (`minComponents:1, maxComponents:1, isOneToOneRelation:true` in the metametadata). APEX **always auto-generates it on import**. If you also declare `attributes ( … )` in the .apx, it validates fine but the import inserts it twice → `ORA-00001 unique constraint … WWV_FLOW_WORKSHEETS_PK` (IR) or `… JET_CHARTS_PK` (chart). Renaming regions, `-id`, rebuilding the workspace, even a brand-new ADB will NOT fix it — it's a double insert inside one import.

Consequences:
- **`column`, `series`, `axis` are direct children of `region`** — not nested under `attributes`.
- **The singleton's property groups are written directly on the region as well.** Chart type is group `chart`, height is group `chartLayout`, so a chart region carries `chart { type: pie }` and `chartLayout { height: 400 }` as siblings of `layout { }` / `source { }`. Same idea for IR attribute groups (`pagination { }`, `searchBar { }`, …). Oracle's own `apex export -exptype APEXLANG` omits these groups when they hold default values, which is why a round-trip export never shows them.
- Never write the word `attributes` inside a region: `attributes ( … )` double-inserts, `attributes { … }` is a syntax error, and a nested `attributes { chart { … } }` silently swallows the sibling `series`.

### Interactive report — columns render only if declared

IR columns are auto-created from the SQL but **hidden** unless each one is declared. Minimum working column:

```apx
region all-transactions (
    name: All Transactions
    type: interactiveReport
    layout {
        sequence: 30
        slot: body
    }
    source {
        location: localDatabase
        type: sqlQuery
        sqlQuery: ```sql
            SELECT id, region, TO_CHAR(amount,'FM$999,990.00') amount, TO_CHAR(sale_date,'Mon DD, YYYY') sale_date
            FROM sales ORDER BY sale_date DESC
        ```
    }
    column ID (
        type: plainText
        heading {
            heading: "ID"
        }
        source {
            dataType: NUMBER
        }
        layout {
            sequence: 10
        }
    )
    column REGION (
        type: plainText
        heading {
            heading: "Region"
        }
        source {
            dataType: STRING
        }
        layout {
            sequence: 20
        }
    )
)
```

- Column identifier = the SQL column alias, UPPERCASE.
- `source.dataType` is **`STRING | NUMBER | DATE`** — APEX internal codes. `VARCHAR2` validates but fails at import with `WWV_FLOW_VALID_WS_COL_TYPE` check constraint.
- `type: plainText` (valid: hidden, link, richText, plainTextBasedOnLov, displayImage, downloadBlob, removeHtml, percentGraph, rowSelector, themeTemplateComponent/…).
- **Every `{ }` group must be multi-line.** `heading { heading: "ID" }` on one line silently fails to parse and the validator reports the property as missing.

### Chart — working pattern

Verified on APEX 26.1.4 with `apex_application_page_charts` showing `CHART_TYPE=Pie/Bar, CHART_HEIGHT=400`. Pie/donut charts take **no** `axis` children (the validator reports "axis x not found" if you add them); bar/line/area need `axis x` + `axis y`.

```apx
region sales-by-region-chart (
    name: Sales by Region
    type: chart
    appearance {
        template: @/standard      # REQUIRED for charts — see bullets below
        templateOptions: #DEFAULT#
    }
    layout {
        sequence: 10
        slot: body
    }
    chart {
        type: bar            # pie | bar | line | area | donut | … (group lives on the region, see singleton rule)
    }
    chartLayout {
        height: 400          # REQUIRED in practice — see bullets below
    }
    series primary (
        name: Total Sales
        execution {
            sequence: 10
        }
        source {
            location: localDatabase
            type: sqlQuery
            sqlQuery: ```sql
                SELECT region AS label, SUM(amount) AS value FROM sales GROUP BY region ORDER BY 2 DESC
            ```
        }
        columnMapping {
            label: LABEL
            value: VALUE
        }
    )
    axis x (
        name: x
    )
    axis y (
        name: y
    )
)
```

- `series` needs `name`, `execution.sequence`, `source`, `columnMapping{label,value}` — that's the whole minimum.
- Do NOT put `type:` on the series — that property (id 864) only exists when chart type is `combo`; otherwise the validator reports "Invalid property: type".
- `axis` identifier AND `name` must both be one of `major | minor | x | y | y2`; the identifier is not auto-mapped to `name` here (unlike `installScript`), and two axes with null names collide as duplicates.
- Bar/line/area charts require both an `x` and a `y` axis; **pie has none** — drop the `axis` blocks or validation fails with COMPONENT_NOT_FOUND.
- **Chart regions need a region template** (`appearance { template: @/standard }`). Without one the region imports as "No Template", which emits no `<div id="R<region_id>">` wrapper; the JET widget then throws `Uncaught Error: Region element not found R…` in the browser console and the page shows "No data to display" — even though the AJAX data call (replayable with curl against `wwv_flow.ajax`) returns perfect rows. Interactive reports don't care because they render their own wrapper. Setting the template on IRs too is worth it anyway: it's what gives them their title bar.
- **Always set `chartLayout { height: 400 }`.** With no height the JET chart renders 0px tall inside the body slot: the page looks completely blank, `apex_workspace_activity_log` shows a clean 0.03s render with no error, and the dictionary rows all look right. This is what "the charts page is empty" means.
- To confirm a chart really landed, query as the parsing schema: `SELECT region_name, chart_type, chart_height, number_of_series, number_of_axes FROM apex_application_page_charts WHERE application_id=:app AND page_id=:pg;`

### Making the app public (no login)

Authentication scheme plugin types accepted by the validator (26.1.2): `oracleApexAccounts, databaseAccounts, ldapDirectory, openDoorCredentials, socialSignIn, oracleAppServerSSO, custom, internalAppExtension, samlSignIn, noAuth, httpHeaderVariable`.

```apx
# shared-components/authentications.apx
authentication no-auth (
    name: No Authentication
    type: noAuth
)

# application.apx
authentication {
    scheme: @no-auth
}
```

Per-page alternative (works with any scheme): `security { authentication: public … }` on the page — the scaffold's login page already uses it. The global page (page 0) rejects the property; leave it alone. Dictionary check: `apex_applications.authentication_scheme` = `No Authentication`, `apex_application_pages.page_requires_authentication` = `No`.

### Oracle's official skills are installed — use them before reverse-engineering anything

`github.com/oracle/skills` is installed under `~/.claude/skills/` as `apexlang` (the full package: EBNF grammar, templates, `tools/apexctl.mjs`, `tools/query-valid-props.mjs`), `oracle-db` and `oracle-oci`. Official route if you'd rather have them as auto-updating plugins: `/plugin marketplace add oracle/skills` then `/plugin install apex@oracle-skills` (also `db@…`, `oci@…`).

What matters in the apexlang package:
- `templates/region-components/chart/*.md` and `templates/page-examples/interactive-report-page/*.example.md` are the canonical shapes. They match everything documented above (groups on the region, `series`/`axis`/`column` as direct children, `@/standard` for charts). They also show real `NUMBER`/`DATE` columns with `appearance { formatMask: FML999G999G999G999G990D00 }` + `heading { alignment: end }` + `layout { columnAlignment: end }` — better than `TO_CHAR` in the SQL, which makes numbers sort as strings — and side-by-side layout via `layout { columnSpan: 6 }` on both regions plus `startNewRow: false` on the second. One thing NOT to copy from their IR example: the `@/interactive-report` region template has no title bar, so report headings disappear; `@/standard` keeps them.
- `node tools/query-valid-props.mjs --compiler-oracle-home /opt/homebrew/Caskroom/sqlcl/<ver>/sqlcl --component chart.series --group columnMapping` gives compiler-backed valid properties/LOVs. Use dotted aliases (`chart.series`, `chart.axis`); `--component series --parent region` doesn't resolve.
- `node tools/apexctl.mjs apexlang validate --app-path <app>` is a style lint (breadcrumb coverage, `DASHBOARD_LAYOUT_ROW_PLAN` wanting `layout.startNewRow: false` + `columnSpan` for side-by-side regions). Failing it does not mean the app won't import.
- **Known false positive:** `apexctl apexlang compiler-truth audit` reports `series`/`axis` as "not valid under parent region". Their own `chart._common.md` (guardrail 13) says the compiler resolves them under `attributes`, and their templates put them directly under `region` — which is the only form that imports. Don't "fix" it.
- Run every `tools/*.mjs` from the package root (`cd ~/.claude/skills/apexlang`).
- The heavier `apexctl runtime validate/roundtrip` gates need a **saved SQLcl connection** (`--db-connection-name`); this project uses wallet + inline credentials, so those gates are unused here. `apex validate` + `apex import` via SQLcl is the equivalent.

### `apex generate` overwrites — keep the finished app out of its path

`apex generate -name … -dir ./projects` always writes to `./projects/starter-app/` and **overwrites every scaffold file** (application.apx back to the scaffold name, `deployments/default.json` emptied, auth back to APEX accounts, `p00001-home.apx` back to the hero-only page, `supporting-objects.apx` without the install script). It does not delete extra files, so a clobbered app looks half-alive. The slide-7 Run button does exactly this — that's how the authored app got wiped mid-session. Hence the split: `projects/sales-dashboard/` is the finished app and the only source of truth; `projects/starter-app/` is demo output and is git-ignored. `09-deploy-app.sh` defaults to `sales-dashboard`.

If the source is ever lost again, the live app is the backup: `apex export -applicationid <id> -exptype APEXLANG -dir <dir>` round-trips cleanly (validated + re-imported). Oracle's exporter writes the install script as `supporting-objects/install-scripts.apx` with `script { contentFile: sales-schema.sql }` — that's the canonical form (the `content: @install-scripts/x.sql` spelling also imports). It omits default-valued groups (e.g. `chart { type: bar }`) and the `location: localDatabase` line.

### Safe way to test a risky change

Import beside the live app instead of over it: `apex import -input … -id 900 -alias SCRATCH`, verify in the dictionary / `curl` the `/scratch/…` URL anonymously, then `APEX_APPLICATION_INSTALL.REMOVE_APPLICATION(900)`. Only then remove and re-import the real alias. This is how the pie-chart and no-auth changes were proven without leaving the demo app broken.

### Verifying what the browser actually shows (no UI, no human)

Server-side checks (dictionary views, activity log, replaying `wwv_flow.ajax` with curl) all passed while the charts page was still visibly broken. The only thing that caught it was rendering the page in headless Chrome and reading the console:

```bash
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
"$CHROME" --headless=new --disable-gpu --no-first-run --user-data-dir=/tmp/hc \
  --window-size=1400,1300 --enable-logging=stderr --v=0 --virtual-time-budget=20000 \
  --screenshot=/tmp/page.png "https://…/ords/r/webinar/sales-dashboard/charts" 2>/tmp/page.log &
# wait until /tmp/page.png exists, then kill the process — Chrome hangs on exit under virtual time
grep CONSOLE /tmp/page.log      # JS errors land here as INFO:CONSOLE lines
```

Then Read the PNG. `--timeout` instead of `--virtual-time-budget` screenshots before JET's async modules run and shows collapsed regions — use virtual time. The no-auth app makes this possible; with a login scheme you'd need to script the login first.

`classicReport` needs the same explicit `column` children plus a `template`; there's no advantage over `interactiveReport` for a demo.

**Format in the SQL, not APEXlang.** `TO_CHAR(amount, 'FM$999,990.00') AS amount` in the SELECT is way faster than adding format-mask properties per column (which again needs the classicReport `column` boilerplate).

### Install scripts do NOT run automatically on `apex import`. They're packaged with the app but only execute when a user first hits the app URL (APEX prompts "install supporting objects?") or via the `APEX_APPLICATION_INSTALL` package (procedure names have moved across versions — check `all_procedures WHERE owner LIKE 'APEX%' AND upper(procedure_name) LIKE '%SUPPORT%'` for the current name in your target APEX version).

# python3 to walk componentTypes, properties, groups — see reference_apexlang_gotchas.md

- 4970 = `installScript`

## Known open items

- `install { scriptFile: X }` parallel to `deinstall { scriptFile: X }` isn't supported; had to use the `installScript` component. If Oracle adds `install { scriptFile }` in a later APEXlang release, the current syntax still works but a simpler form would be nicer.
- `apex import` accumulates apps (each run creates a new ID + alias `starter-app`, `starter-app102`, …). If a cleaner "same app, updated in place" is needed, look into `apex import -id <existing>` (untested).
- `APEX_APPLICATION_INSTALL.INSTALL_SUPPORTING_OBJECTS` doesn't exist in APEX 26.1.4 under that name — for programmatic install triggering the audience should just visit the app URL and follow the install wizard. Alternatively, run the install SQL directly with `sql @install-scripts/sales-schema.sql` as the workspace schema.
- The deck's slide 10 shows a plain-English prompt as the "one-shot" the agent processes; the agent (you, next time) should be able to fulfill it by running scripts 07→08→09 in sequence.

## Bridge notes

`bridge.py` opens/reuses a Terminal.app or iTerm2 tab titled `webinar-demo` and types Run-button commands into it via AppleScript. Auto-detects terminal on startup; override with `--terminal iterm2 | terminal`. Dry-run mode (`--dry-run`) logs commands without executing. The webinar-demo tab starts in the project directory so `bash scripts/xx.sh` just works.
